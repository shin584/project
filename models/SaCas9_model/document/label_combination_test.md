

# [Test Log] 데이터 전처리 및 학습 라벨 조합에 따른 모델 성능 테스트


## 1. 원시 데이터 라벨 조합 및 학습 트러블슈팅

### 1.1. 테스트 배경

기존 학습 파이프라인에서는 `A375 viability`와 `MOLM13 viability` 두 라벨의 데이터(총 3,610개)를 사용하고 있었습니다. 데이터 분석 결과, 입력되는 DNA 서열은 동일하지만 세포주(Cell line) 환경의 차이로 인해 정답(Label) 값이 다르게 매핑되어 있음을 확인했습니다. 이를 바탕으로 데이터 조합을 변경하며 성능 변화를 테스트했습니다.

### 1.2. 시도 1: 동일 서열 정답 평균화

* **가설:** 동일한 입력 서열에 대해 서로 다른 정답이 절반씩 존재하는 것이 모델의 혼동을 유발하고 성능 하락의 원인일 것이라 가정했습니다. 이를 해결하기 위해 두 라벨의 정답 점수를 평균 내어 학습을 시도했습니다.
* **결과:** 예상과 달리 모델의 예측 성능이 오히려 **하락**했습니다.

### 1.3. 시도 2: 데이터 볼륨 최대화 (약 7,000개)

* **가설:** 시도 1의 성능 하락 원인이 '절대적인 데이터 분량 부족'에 있다고 판단했습니다.
* **방법:** 정제 필터를 풀고 `293T viability`, `A375 viability`, `MOLM13 viability`, `A375 PLX`, `A375 6TG`, `293T 6TG` 등 가용한 6개 라벨의 모든 서열(약 7,000개)을 모델 입력으로 일괄 투입하여 학습을 시도했습니다.
* **결과:** 성능이 이전보다 더욱 심각하게 **하락**했습니다.
* **원인 분석:** `A375 PLX`, `A375 6TG`, `293T 6TG` 라벨은 독성 물질(약물)이 주입된 특수 환경에서의 생존율 데이터입니다. 순수한 절단 메커니즘과 완전히 반대되는 양상의 점수 분포를 가지므로, 모델 학습에 치명적인 교란 변수(노이즈)로 작용한 것으로 분석됩니다.

### 1.4. 시도 3: 순수 생존율 데이터 통합 (약 5,000개)

* **방법:** 노이즈로 판명된 약물 처리 데이터를 완벽하게 배제하고, 순수하게 DNA 절단 생존율을 나타내는 `293T viability`, `A375 viability`, `MOLM13 viability` 3가지 라벨의 서열(약 5,000개)만을 선별하여 학습을 재시도했습니다.
* **결과:** 이전 모델 대비 **유의미한 성능 향상**이 나타났습니다.

---

## 2. 최종 결론 (Lessons Learned)

딥러닝 모델의 성능을 한계점 이상으로 끌어올리기 위해서는 절대적인 데이터의 양(Quantity)뿐만 아니라, 모델의 목적 함수에 정확히 부합하는 데이터의 질(Quality, 순도)이 모두 동시에 확보되어야 합니다. 맹목적인 데이터 증강(Data Augmentation)은 오히려 노이즈를 발생시켜 성능 저하를 초래할 수 있음을 실험적으로 증명했습니다.
