# Cas12a 5-fold 성능 측정 (#92)

**결론: 채택 gate 통과. Spearman 0.7509 ± 0.0085 로 ridge 기준선 0.738 을
+0.0129 상회했고, 요구 조건인 fold 표준편차(0.0085)의 1.52배다.**
이 모델의 성능 수치가 **처음으로** 존재한다 (리뷰 §3 P1 해소).

단 **여유는 크지 않다.** margin/std = 1.5 는 gate 를 넘지만, 3-scale CNN + BiLSTM 이
선형 모델 대비 얻은 것은 Spearman 0.013 이다. 리뷰 §2 의 "복잡도를 정당화하지
못한다"는 지적이 완전히 해소된 것은 아니다 — 아래 [해석](#해석) 참조.

수치의 유일한 출처는 `cas12a/artifacts/cas12a_5fold_metrics.json` 이다. 이 문서는
그 JSON 의 요약이며, 재측정하면 JSON 이 갱신된다. 학습 로그는 산출물이 아니므로
보존하지 않는다.

## 측정 조건

| 항목 | 값 |
| --- | --- |
| 데이터 | `kim_2018_cas12a_dataset.xlsx`, usable 15,000행 (34bp) |
| 분할 | `KFold(n_splits=5, shuffle=True, random_state=42)` — **변경 없음** |
| 모델 | `create_cas12a_model()`, 파라미터 96,513개 — **구조 변경 없음** |
| epoch | 상한 100, `EarlyStopping(val_loss, patience=10, restore_best_weights=True)` |
| LR | Adam 5e-4, `ReduceLROnPlateau(factor=0.5, patience=5, min_lr=1e-5)` |
| 시드 | Python/NumPy/TF = 42 (fold 별 `42 + fold`), `enable_op_determinism()` 미적용 |
| 환경 | Windows 11, Python 3.13.7, TF 2.21.0 (CPU 전용), NumPy 2.3.2, SciPy 1.16.1, scikit-learn 1.7.1 |
| 명령 | `python -m cas12a.train` (인자 없음) |

분할과 구조를 건드리지 않은 것이 중요하다. gate 가 ridge 기준선과의 **상대** 비교이고
그 기준선은 동일 피처·동일 분할에서 산출됐으므로, 둘 중 하나라도 바뀌면 0.738 과의
비교가 성립하지 않는다 (ADR 0003).

## 기준선 대비

| 모델 | MSE | MAE | R² | Spearman |
| --- | --- | --- | --- | --- |
| 평균값 예측 | 0.1039 | 0.2837 | 0.00 | — |
| RidgeCV (선형) | 0.0481 ± 0.0008 | 0.1705 | 0.537 | 0.738 |
| **CNN+BiLSTM (#92)** | **0.0450 ± 0.0012** | **0.1568 ± 0.0038** | **0.5668 ± 0.0107** | **0.7509 ± 0.0085** |
| 노트북 CNN+BiLSTM (5 epoch) | 0.0439~0.0481 | 0.1556~0.1641 | ~0.54~0.58 | 미측정 |
| *DeepCpf1 (참고선)* | — | — | — | *≈0.77* |

**gate 판정**: `0.7509 - 0.738 = +0.0129 >= 0.0085` → **통과**.

개선은 Spearman 한 지표만의 현상이 아니다. MSE·MAE·R² 전부 ridge 를 같은 방향으로
앞선다 (MAE -8.0%, MSE -6.4%, R² +0.030). 네 지표가 함께 움직인다는 점이 0.013 이라는
작은 Spearman 차이를 단순 잡음으로 보기 어렵게 만든다.

**DeepCpf1 의 0.77 은 gate 가 아니다** (ADR 0003). 분할·전처리가 다르므로 0.7509 와
직접 비교할 수 없고, 못 넘은 원인이 구조인지 조건 차이인지 판정할 수 없다.

## 보조 지표 — 보정 (calibration)

앱이 Cas type 간 **절대값**을 비교하므로, 순위만 맞고 절대 수준이 어긋나면 교차 비교가
깨진다. `truth ~ slope × pred + intercept` 로 측정한다 (완벽: slope 1, intercept 0,
bias 0).

| fold | slope | intercept | mean bias |
| --- | --- | --- | --- |
| 1 | 1.007 | 0.021 | -0.0239 |
| 2 | 0.963 | 0.022 | -0.0071 |
| 3 | 0.905 | 0.039 | -0.0001 |
| 4 | 0.954 | 0.044 | -0.0265 |
| 5 | 0.893 | 0.032 | +0.0132 |
| **평균 ± 표준편차** | 0.9446 ± 0.0413 | 0.0317 ± 0.0092 | -0.0089 ± 0.0148 |

**보정은 양호하다.** 평균 편향 -0.0089 는 0-1 척도에서 1%p 미만이고 fold 간 부호도
일정하지 않다 (3개 음수, 1개 양수, 1개 ~0). slope 0.945 < 1 과 intercept +0.032 는
예측이 실제보다 약간 넓게 퍼져 있다는 뜻 — 낮은 구간은 조금 과소, 높은 구간은 조금
과대 예측한다. 교차 Cas 비교를 깨뜨릴 수준의 전역 이동(shift)은 없다.

## 해석

**P1 해소.** 지표가 존재한다. 리뷰 §2 가 "미측정"으로 비워둔 Spearman 칸이 채워졌고,
ridge 와의 비교가 처음으로 가능해졌다.

**P2 의 실제 피해가 확인됐다.** 5개 fold 모두 best epoch 이 마지막 epoch 이 아니다
(3/13, 7/17, 8/18, 9/19, 6/16). `restore_best_weights` 없이는 이 다섯 fold 전부
과적합이 진행된 뒤의 가중치를 들고 있었을 것이다 — fold 1 은 epoch 3 이후 10 epoch 을
더 돌며 train loss 0.023 까지 내려가는 동안 `val_loss` 는 0.0472 → 0.048대로 올랐다.
동시에 **노트북의 `epochs=5` 가 크게 틀린 값은 아니었다**는 것도 드러난다: best epoch
의 중앙값은 7이고, 5 epoch 은 수렴 지점에 근접해 있었다. P2 의 핵심 피해는 "학습이
너무 짧았다"보다 **"어느 epoch 에서 멈췄는지에 수치가 좌우됐다"** 쪽이다.

**복잡도 정당화는 여전히 미완이다.** gate 를 넘었으므로 이 이슈의 판정은 "채택"이지만,
96,513 파라미터 CNN+BiLSTM 이 선형 ridge 대비 얻은 것은 Spearman +0.0129 다.
리뷰 §P6 의 가설 — 352차원 dinuc 피처가 CNN 입력 one-hot 에서 완전히 유도 가능하므로
별도 Dense 분기가 새 정보를 주지 않는다 — 은 이 측정으로 반박되지도 입증되지도 않았다.
`GlobalAveragePooling1D` 가 BiLSTM 출력의 위치 정보를 평균으로 소거하는 문제도 그대로다.
**이 둘은 gate 통과와 무관하게 유효한 개선 여지**이며, 다루려면 별도 이슈여야 한다
(이 이슈 범위 밖).

**다음 구조 변경 시도부터는 held-out 분리가 필요하다.** 이번 측정은 구조를 고르는 데
쓰이지 않았으므로(한 번의 설정 수정을 fold 로 측정한 것) fold 지표가 아직 오염되지
않았다. 그러나 P6 나 pooling 교체를 시도해 fold 지표로 구조를 고르기 시작하는 순간
이 수치는 성능 추정치가 아니게 된다. 근거와 발동 조건은 ADR 0003 에 기록했다.

## 산출물

같은 디렉터리에 둘이 함께 있다 (#92 작업 5):

| 파일 | 내용 | 추적 |
| --- | --- | --- |
| `cas12a/artifacts/cas12a_5fold_metrics.json` | fold 별 지표 + 분할·학습 설정·라이브러리 버전 + gate 판정 | 커밋 |
| `cas12a/artifacts/cas12a_best_fold4.keras` | val Spearman 최고 fold (fold 4, 0.7576) | `.gitignore` |

중요한 것은 비트 단위 동일성이 아니라 **이 `.keras` 가 어떤 수치를 낸 모델인지가 파일
옆에 남는 것**이다. JSON 의 `saved_model` 블록이 파일명·fold·그 fold 의 Spearman·MAE·
`val_loss` 를 적어 둔다. 시드는 고정했으나 `enable_op_determinism()` 은 적용하지 않았으므로
재실행은 "가까운 값"이지 동일한 값이 아니다 (ADR 0003).

`.keras` 를 커밋하지 않는 것은 9-Hydra 의 `training_log.json` 과 같은 방침이다 —
JSON 은 작고 재현 기록이므로 추적하고, 가중치는 크고 **채택 결정이 난 뒤에야** 의미가
있으므로 그때 `models/` 로 들어간다.

### fold 4 라는 이름에 대한 주의

운영 중인 `e_system/models/cas12a_model_fold_4.keras` (7월 파일) 와 이번 산출물이
모두 "fold 4" 인 것은 **우연이다.** 분할 시드가 같으므로 fold 4 가 검증한 행 집합은
동일하지만, 7월 파일은 노트북의 5-epoch 실행에서 나왔고 그 수치는 기록되지 않았다.
두 파일은 같은 모델이 아니다.

교체 여부는 이 이슈 범위 밖이다 (본문 "결과에 따른 분기"). 교체한다면 이 JSON 이
함께 가야 한다 — 수치 없는 가중치 파일을 다시 만드는 것이 P4 의 재발이다.
