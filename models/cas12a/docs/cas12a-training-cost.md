# Cas12a 학습 CPU 비용 측정 (#93 작업 6)

**결론: 로컬 CPU 로 5-fold 전체가 4분 18초에 끝난다. #92 를 로컬에서 돌리는 데
비용상의 장애물은 없다.** 본문에 적힌 "CPU 로 완주 가능하다"는 추정은 맞았고,
여유도 예상보다 크다.

## 측정 환경

| 항목 | 값 |
| --- | --- |
| CPU | Intel Core i5-8265U @ 1.60GHz (4코어 / 8스레드) |
| GPU | 없음 — `list_physical_devices('GPU')` 빈 리스트, `is_built_with_cuda()` False |
| TensorFlow | 2.21.0 (oneDNN 최적화 on) |
| 데이터 | `kim_2018_cas12a_dataset.xlsx`, usable 15,000행 (34bp) |
| 학습 설정 | `epochs=5`, `batch_size=32`, `KFold(5, shuffle=True, random_state=42)` |
| 모델 | 파라미터 96,513개, 375 step/epoch (12,000행 ÷ 32) |

명령: `python -m cas12a.train` (인자 없음 — 기본 데이터셋 경로).
TensorFlow 2.11 부터 native Windows GPU 지원이 없으므로 이 수치는 CPU 전용이며,
WSL2 로 옮기지 않는 한 바뀌지 않는다 (ADR 0002).

## 측정값

| fold | wall-clock | per-epoch |
| --- | --- | --- |
| 1 | 55.8s | 11.2s |
| 2 | 56.7s | 11.3s |
| 3 | 47.8s | 9.6s |
| 4 | 47.7s | 9.5s |
| 5 | 48.4s | 9.7s |
| **5-fold 전체** | **257.5s (4분 18초)** | — |

**1 epoch ≈ 9.5~11.3초, 1 fold ≈ 48~57초.** fold 1-2 가 fold 3-5 보다 약 18% 느린데,
학습량은 fold 마다 동일하므로(12,000행 고정) 모델이 아니라 환경 쪽 변동이다 —
첫 fold 의 커널 워밍업과 측정 중 머신 상태로 보인다. 단일 측정이므로 이 차이에
의미를 두지 않는다. 데이터 로딩(xlsx 파싱 + 피처 추출 15,000행)은 fold 합계 256.4초와
전체 257.5초의 차이, 즉 **1초 내외**로 무시 가능하다.

### #92 에 대한 함의

epoch 당 10초라는 것은 **P2(학습 부족)를 고치는 비용이 사실상 없다**는 뜻이다.
`epochs=5` → `50` 으로 올리고 `EarlyStopping` 을 붙여도 5-fold 전체가 최악의 경우
40분대고, early stopping 이 실제로 걸리면 그보다 짧다. Colab 으로 되돌릴 이유가 없다.

따라서 #92 의 `ready-for-human` 근거(Colab 마운트)는 해소됐고, 비용 측면에서도
`ready-for-agent` 재라벨을 막을 것이 없다. 재라벨 판단 자체는 이슈 소유자의 몫이다.

## 참고 — 수렴값 (패리티 기준 아님)

#93 작업 5 에 따라 수렴값은 패리티 기준에서 **제외**한다. 학습은 확률적이고
시드가 고정되지 않았으며(P4) CPU/GPU 커널이 다르므로, 아래 수치는 "노트북 보고치와
같은 자리수 범위에 드는지"만 보기 위한 참고다. 어떤 테스트도 이 값에 단정하지 않는다.

| fold | epoch 5 `val_loss` | 그 fold 의 최저 `val_loss` |
| --- | --- | --- |
| 1 | 0.0467 | 0.0460 (epoch 3) |
| 2 | 0.0447 | 0.0445 (epoch 3) |
| 3 | 0.0433 | 0.0430 (epoch 4) |
| 4 | 0.0440 | 0.0440 (epoch 5) |
| 5 | 0.0463 | 0.0456 (epoch 4) |

노트북 보고치는 fold 4 epoch 5 의 `val_loss 0.0481` 이다. 이 실행의 fold 4 는 0.0440,
전체 범위는 0.0433~0.0467 로 **같은 자리수**다. 포팅이 수렴을 망가뜨리지 않았다는
정도의 확인이며, 그 이상은 주장하지 않는다.

**P2 가 그대로 재현된다.** 5개 fold 중 4개에서 마지막 epoch 이 그 fold 의 최저점이
아니다 (fold 1 은 epoch 3 대비 +0.0007, fold 3 은 epoch 4 대비 +0.0003, fold 5 는
epoch 4 대비 +0.0007). `restore_best_weights` 가 없으므로 남는 가중치는 마지막
epoch 의 것이고, 보고되는 수치는 리뷰가 지적한 그대로 **어느 epoch 에서 멈췄는지에
좌우된다.** 차이 자체는 작지만, 5 epoch 에서 아직 수렴 중이라는 신호이기도 하다 —
#92 가 epoch 상한을 올릴 근거다.

**지표는 여전히 없다.** 위 값은 Keras 가 epoch 마다 찍은 로그를 읽은 것이고,
`train_5fold` 의 `fold_results` 는 포팅 후에도 빈 리스트다 (P1, #92 범위).
Spearman/Pearson/R² 는 측정되지 않았으므로 §2 의 ridge 기준선(0.738)과
비교할 수 있는 수치는 이 실행에서 나오지 않는다.
