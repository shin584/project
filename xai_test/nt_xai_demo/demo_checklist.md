# NT XAI 데모 시연 체크리스트

실행: 저장소 루트에서 `python -m xai_test.nt_xai_demo` (REPL). 한 뷰만 보려면
`python -m xai_test.nt_xai_demo cas12a report`처럼 일회성으로도 같은 글이 나온다.

아래 명령은 REPL 프롬프트를 붙인 `cas12a> report` 꼴로 적었다 — 프롬프트가 그 뷰를 보려면
어느 뉴클레아제가 선택돼 있어야 하는지까지 말해 준다. 입력하는 것은 `>` 뒤쪽뿐이다.
(`cross`는 선택과 무관하므로 프롬프트가 무엇이든 같은 글이 나온다.)

이 데모는 **저장된 산출물만** 읽는다. 모델을 로드하지 않고 새로 계산하지 않으며,
두 뉴클레아제의 수치를 나란히 두지 않는다 (ADR 0012).

## 미팅 직전 (화면 켜기 전)

- [ ] `python -m xai_test.nt_xai_demo verify` → "온전성 확인 통과"
- [ ] `python -m pytest xai_test/nt_xai_demo/test -q` 통과
- [ ] 콘솔이 한글과 ASCII 막대(`#`)를 깨뜨리지 않는다 (Windows cp949는 진입점에서 UTF-8로
      자동 전환된다 — 전환이 안 되면 뷰가 중간에 `UnicodeEncodeError`로 멈춘다)

## 순서

진행은 **Cas12a → SpCas9 → 교차**다. 각 뉴클레아제를 그 분석 안에서 끝내고 넘어가야,
마지막 `cross`가 "비교가 아니라 각자의 소견 둘"로 읽힌다.

### 0. 셸 시작 — 선택 안 된 상태

- [ ] 프롬프트가 `(선택 안 됨)>`이고 머리글에 "모델을 로드하지 않고 두 뉴클레아제의 수치를
      비교하지도 않는다"가 보인다
- [ ] 🗣 **말할 지점 ①**: 뉴클레아제를 먼저 고르는 것은 불편이 아니라 설계다 — 두 분석은
      공통 축이 없어 한 화면에 올릴 수 없다

### 1. NT-Cas12a (`cas12a`)

- [ ] `cas12a> report` — 모집단/coverage, PAM 집단 3개, rollout 해석 제한
  - [ ] 성능이 all / TTTV / TTTT **세 집단 모두** 보이고 (집단마다 Spearman·MAE의
        raw/clipped 두 줄씩) 풀링 문구가 붙는다
        (전체 raw Spearman 0.7007은 두 군의 평균 효율 차이를 포함하고, 군 내부 순위는
        TTTV 0.5423 / TTTT 0.2995)
  - [ ] rollout 퇴화(1500/1500)가 **해석 제한**으로 적혀 있다 (저장·수치 실패가 아니다)
  - [ ] 화면 맨 아래 "주장 범위"가 보인다
  - [ ] 🗣 **말할 지점 ②**: 0.7007은 군을 합친 값이라 모델의 순위 능력으로 읽지 않는다
- [ ] `cas12a> agreement` — IG-ISM 일치도(판정 없음)와 ISM 위치 프로파일 3개
  - [ ] ASCII 막대에서 PAM 구간이 괄호로 묶여 있고 최대 민감 위치(7)가 그 안에 있다
  - [ ] 일치도에 합격/불합격 문구가 없다
  - [ ] 저장된 SVG는 **경로만** 출력된다 (열지 않는다 — SpCas9에 대응물이 없다)
- [ ] `cas12a> cases` — 기술 사례 15건, 역할별 후보 수와 함께
  - [ ] `low_error`의 분모가 375가 아니라 **372**이고 (`exclude_previous`) 화면에 그 배제가
        보인다
- [ ] `cas12a> explain 13768:high_error` — 15건은 네 방법을 모두 보유한다 (IG 부재 경로가 없다)

### 2. 9-Hydra v3, SpCas9 (`spcas9`)

- [ ] `spcas9> report` — 모집단, IG-ISM 일치도(판정 없음), head 순서 역전
  - [ ] 노이즈 바닥이 **head 순서 역전 문맥에만** 나오고 head별 값(6.37 / 6.97 / 0.99 %p)이다
  - [ ] 일치도 0.70에 합격 판정이 없고 `mismatch_note`가 함께 뜬다
  - [ ] 🗣 **말할 지점 ③**: 노이즈 바닥(%p)과 일치도(무차원 순위 상관)는 단위도 대상도 달라
        연결하지 않는다 — 순서 역전은 head 3개를 유지하는 이유다
- [ ] `spcas9> agreement` — generalisation 층과 pam_library 층이 **따로** 나온다
  - [ ] 두 층을 합친 수치가 어디에도 없다 (`"pooling": "forbidden"`)
  - [ ] 모든 수치가 층·head·통계 종류·실제 분모를 함께 적는다 (200행·193타깃 / 200행·5타깃)
- [ ] `spcas9> cases` — 사례 18건, 전부 `split=test`
- [ ] **`spcas9> explain GEN-HEADGAP-02`** — 시연용 본 사례 (row 17068)
  - [ ] 18건 중 **IG 고정 명단 400행에 든 유일한 사례**다 — 세 head의 ISM·IG가 모두 나온다
  - [ ] `pam_plus_right_flank` 토큰이 SpCas9 head의 ISM·IG 최대다
  - [ ] rollout이 "있음 — 다만 head별 읽기를 줄 수 없다 (ADR 0008)"로 적혀 있다
  - [ ] split 역할(test)이 표시된다
- [ ] `spcas9> explain GEN-ERRHI-01` — 나머지 17건이 타는 **IG 부재 경로**
  - [ ] "이 행은 IG 고정 명단 400행에 없음"이 사유와 함께 뜬다 (명단은 사례 선정 전에 고정됐다)
  - [ ] 🗣 **말할 지점 ④**: 없는 방법을 빈칸으로 두지 않고 왜 없는지 적는다

### 3. 교차 소견 (`spcas9> cross`, 선택과 무관)

- [ ] 머리글이 "정성적, 수치 비교 없음"이고, 소견보다 먼저 나오는 `이 분석이 답한 질문`
      블록이 "묻지 않은 것"으로 끝난다 (어느 쪽이 더 민감·정확한가는 묻지 않는다)
- [ ] 소견이 **하나**다: 두 모델 모두 최대 민감 구간이 자기 PAM과 겹친다
- [ ] SpCas9 네 수치(ISM 0.115 / 나머지 0.016-0.033, IG 2.024 / 나머지 0.14-0.27)에
      **200행·193타깃**이 분모로 적혀 있고, library 층 대응값(0.0996 / 1.090)은 따로 표시된다
- [ ] `[비교하지 않는 것]` 절에 성능 지표와 IG-ISM 일치도 수치가 모두 들어 있다
- [ ] 🗣 **말할 지점 ⑤ (이 데모의 핵심 문장)**: **이 수치는 비교하지 않는다.** 소견의 방향이
      같을 뿐이고, PAM 방향(SpCas9 3′ / Cas12a 5′)도 해상도(토큰 5개 / 위치)도 반대다.
      그리고 이 전부는 모델의 내부 정보 사용에 대한 기술이며 물리적 DNA/단백질 결합에 대한
      주장이 아니다.

## 질문이 나오면

- "어느 모델이 더 좋나?" → 답할 수 없는 질문이다. 데이터셋·분할·라벨 정의가 달라 공통
  축이 없다 (ADR 0012). 각 `report`에서 그 모델의 모집단과 함께 본다.
- "일치도 0.70이면 합격인가?" → 합격선이 없다. IG와 ISM은 해상도가 다르고 서로의 정답이
  아니다 (ADR 0007).
- "지금 모델을 돌리는 건가?" → 아니다. 저장된 산출물을 읽고 `manifest.json`으로 체크섬한다.
- "v2나 CNN은?" → 범위 밖이다. 그 모델들의 IG/ISM은 산출된 적이 없고 새 GPU 계산이 필요하다.
