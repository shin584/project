# NT XAI 데모 시연 체크리스트

실행: 저장소 루트에서 뉴클레아제를 첫 인자로 준다.

- `python -m xai_test.nt_xai_demo cas12a` — NT-Cas12a REPL
- `python -m xai_test.nt_xai_demo spcas9` — 9-Hydra v3 (SpCas9) REPL
- 입력을 하나 붙이면 (`... cas12a B1`) 같은 화면이 한 번만 나오고 끝난다

뉴클레아제는 시작할 때 고정된다. 세션 안에서 바꿀 수 없고, 두 뉴클레아제가 한 화면에
오르지 않는다. 다른 쪽을 보려면 `quit` 후 다시 띄운다.

입력은 두 가지고, 어느 쪽이든 결과는 **그 표적 한 장의 화면**이다 (실측/예측/오차 ·
ISM 막대 · IG 토큰 · rollout · 출처 한 줄).

| 입력 | 예 | 뜻 |
|---|---|---|
| 사례 번호 | `B1` | 오차·head 불일치로 미리 고른 사례 (`help`가 목록을 적는다) |
| 생서열 | Cas12a 34bp 타깃 / SpCas9 30bp 창 | 저장된 행에서 찾아 같은 화면을 연다 |

그 밖에 `report` (성능 + IG–ISM 일치도 + 한계), `help`, `quit`뿐이다.

아래 명령은 프롬프트를 줄여 `cas12a> B1` 꼴로 적었다. 실제 프롬프트는
`cas12a [번호 | 34bp 타깃 서열]>`처럼 입력 단위까지 적는다. 입력하는 것은 `>` 뒤쪽뿐이다.

이 데모는 **저장된 산출물만** 읽는다. 모델을 로드하지 않고 새로 계산하지 않으며,
두 뉴클레아제의 수치를 나란히 두지 않는다 (ADR 0012와 #169 개정).

## 미팅 직전 (화면 켜기 전)

- [ ] `python -m xai_test.nt_xai_demo verify` → "온전성 확인 통과"
- [ ] `python -m pytest xai_test/nt_xai_demo/test -q` 통과
- [ ] 콘솔이 한글과 막대 문자(`▁▂▃…█`)를 깨뜨리지 않는다 (Windows cp949는 진입점에서
      UTF-8로 전환된다 — 전환이 안 되면 화면이 중간에 `UnicodeEncodeError`로 멈춘다)

## 흐름 — 번호 하나를 골라 한 장을 연다

두 뉴클레아제에서 하는 일은 같다: `help`로 번호 목록을 보고, 번호 하나로 화면 한 장을
연다. 시간이 남으면 그 화면의 서열을 그대로 붙여 넣어 같은 화면이 열리는 것을 보인다.

### 1. NT-Cas12a

- [ ] 머리글에 "저장된 산출물만 읽는다 (모델 로드 없음)"과 번호 목록이 보인다
      (A1–A5 low_error · B1–B5 high_error · C1–C5 out_of_range)
- [ ] `cas12a> B1` — 본 사례 (source_row 13768, TTTT, 오차 0.8425)
  - [ ] ISM 막대의 이 행 최대가 PAM 괄호(`[--]` 4-7) 안, 위치 7이다
  - [ ] IG가 DNA 토큰 9개(6-mer 5개 + 단일염기 4개)로 `layout.json` 구간 그대로 나온다
  - [ ] rollout 아래 "물리적 결합의 근거가 아님"이 붙는다
  - [ ] 출처 줄에 층·head·통계·분모(이 행 1행)·선정 근거(high_error 후보 375행 중 rank 1)
  - [ ] 🗣 **말할 지점 ①**: 이 한 장이 데모가 하는 일 전부다 — 표적 하나를 주면 그 표적의
        XAI 결과를 보여 준다. 사례는 오차로 고른 행이라 모집단 요약으로 읽지 않는다
- [ ] (선택) `cas12a> TTAATTTTGGGGACTGCCTGGTGCGCTCCAAGGG` — B1의 서열. 머리글이
      "서열 입력 … (= 사례 B1)"로 바뀌고 본문은 같다
- [ ] (질문이 나오면) `cas12a> report` — coverage 1,500/1,500, PAM 집단 3개, rollout 제한
  - [ ] all 0.7007에 "TTTV·TTTT 풀링" 문구가 붙고 군 내부 순위는 TTTV 0.5423 / TTTT 0.2995
  - [ ] 🗣 **말할 지점 ②**: 0.7007은 군을 합친 값이라 모델의 순위 능력으로 읽지 않는다

### 2. 9-Hydra v3, SpCas9

- [ ] 번호 목록이 A1–A3 ERRLO · B1–B3 ERRHI · C1–C3 HEADGAP (generalisation 층 9개)
- [ ] `spcas9> C2` — 본 사례 **GEN-HEADGAP-02** (row_index 17068)
  - [ ] 머리글이 "head 2개: evoCas9가 SpCas9 대비 오차 차이 최대"로 왜 이 두 head인지 적는다
  - [ ] 사례 9개 중 **IG 고정 명단 400행에 든 유일한 사례**다 — IG 토큰 5개가 값으로 나온다
  - [ ] `pam_plus_right_flank` (24-29)가 SpCas9 head의 ISM·IG 최대다
  - [ ] rollout에 "head 축이 없어 head별 값이 아니다 (ADR 0008)"가 붙는다
  - [ ] 🗣 **말할 지점 ③**: 두 head를 한 화면에 둔 것은 비교가 아니라 이 행이 뽑힌 이유다
- [ ] `spcas9> B1` — GEN-ERRHI-01, **IG 부재 경로**
  - [ ] IG 자리가 빈칸이 아니라 "이 행은 비대상 (고정 명단 400행, 사례 선정 전에 자기 seed로
        고정)"으로 사유와 함께 뜬다
  - [ ] 🗣 **말할 지점 ④**: 없는 방법을 빈칸으로 두지 않고 왜 없는지 적는다
- [ ] (질문이 나오면) `spcas9> report` — 층 2개가 따로, 합친 수치는 어디에도 없다
      (`"pooling": "forbidden"`), 분모는 200행·193타깃 / 200행·5타깃

## 질문이 나오면

- "어느 모델이 더 좋나?" → 답할 수 없는 질문이다. 데이터셋·분할·라벨 정의가 달라 공통
  축이 없다 (ADR 0012). **이 수치는 비교하지 않는다** — 그래서 두 뉴클레아제가 한 세션에
  같이 뜨지도 않는다. 각 `report`에서 그 모델의 모집단과 함께 본다.
- "일치도 0.70이면 합격인가?" → 합격선이 없다. IG와 ISM은 해상도가 다르고 서로의 정답이
  아니다 (ADR 0007).
- "지금 모델을 돌리는 건가?" → 아니다. 저장된 산출물을 읽고 `manifest.json`으로 체크섬한다.
- "아무 서열이나 넣으면 되나?" → 저장된 행에 있는 서열만 된다. 없으면 "저장된 N행에 없음"과
  예시 몇 개가 뜬다. 새 서열은 모델 실행이 필요하고 이 데모는 모델을 로드하지 않는다.
- "v2나 CNN은?" → 범위 밖이다. 그 모델들의 IG/ISM은 산출된 적이 없고 새 GPU 계산이 필요하다.
