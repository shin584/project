# #205 구현 인계

사용자는 Q17 승인에 이어 Q1~Q17·검토한 테스트 경계·필수 검증 범위의 최종 확인에도
"그렇게해"라고 답했다. 설계 확정·구현 준비 완료이며 구현은 별도 작업으로 남아 있다.

- 원격 확정 명세: [#205](https://github.com/shin584/project/issues/205), `ready-for-agent`, OPEN.
- 확정 로컬 명세: [issue205-spec.md](issue205-spec.md).
- 합의 기록: [issue205-interview.md](issue205-interview.md).
- 용어: [CONTEXT.md](../../CONTEXT.md).
- 근거 보존 결정: [ADR 0002](../adr/0002-preserve-runtime-verification-provenance.md).
- 작업 위치·테스트 범위: [AGENTS.md](../../AGENTS.md).

## 작업 위치와 현재 상태

`C:/project/MC_project/dashboard_v3`, 브랜치 `dashboard_v3`, 기준 HEAD
`c7df95b22683fbcefc0e560266bff01ef6190dc2`. 상위 작업 폴더는 다른 브랜치이며
관련 없는 변경이 많다. 기존 데스크톱 프로그램과 다른 워크트리를 보존한다.
후속 변경이 있으면 실제 상태를 먼저 확인하고 통합·검증 기준을 다시 고정한다.

용어집 변경, ADR, 인터뷰·명세·성능 기록·원시 자료·게시 메타데이터는 로컬에
있으며 아직 커밋·푸시하지 않았다. 원격 #205 본문은 로컬 파일에 접근하지 않아도
확정 범위를 이해할 수 있게 작성했다. 최종 공동 이해 확인을 마쳤으며 원격 본문·라벨과
로컬 명세의 동기화 결과는 [게시 기록](issue205-publication/publication.json)에 보존한다.

## 완료한 일

- 기존 코드·계약·실행 자료와 이슈를 읽고 설계 인터뷰 Q1~Q17을 기록했다.
- Q17은 필수 실패 `fail`/비0, 미검증·float64 불가/시간 제한 `incomplete`/비0,
  필수 검증 통과 및 조사 완료 후 원인 미해결/적합 후보 없음 `completed_with_findings`/0,
  필수 검증·해당 조사 완료와 기준 충족 `pass`/0으로 확정했다. 필수 실패가 우선한다.
- 설계 트리와 기존 CLI/SHAP/캐시·취소 테스트 경계를 점검했다. Q17 판정·후보 선정·
  예산 종료의 공개 경계 회귀를 명시했고 새 미확정 설계 선택은 발견하지 못했다.
- 사용자가 Q1~Q17·검증 범위를 최종 설계로 확정했다. 질문과 설계 검토를 완료했다.
- [성능 기록](../runtime/issue205-performance.md)과
  [원시 자료](../benchmarks/issue205-performance-20261118/)를 보존했다.
  non-NT S1/C1의 탐색 성능 호출 52회 완료이며 수치 품질 통과 검증이 아니다.
  Cas12a의 종료 상태는 raw의 마지막 `running`이 아닌 orchestration의 timeout을 따른다.
- #205의 이전 본문과 이전 로컬 명세를 [게시 기록 디렉터리](issue205-publication/)에
  보존했다. 처음 게시할 때 `ready-for-agent`를 적용했으나 다음 세션을 구현으로
  인계한 것은 잘못이었다. 이전 세션에서 사용자 정정에 따라 본문·라벨을 설계 진행 중으로
  정정했다. 이번에는 최종 확인을 받은 뒤 최종 명세와 `ready-for-agent` 상태를 게시했고,
  원격 본문과 로컬 명세의 일치를 확인했다. 이전 상태와 게시 결과·checksum을 보존했다.
- 문서 템플릿·내용·상대 링크·diff와 성능 원시 자료 checksum을 확인했다.

## 아직 수행하지 않은 일

- 검증·종합 판정·버전/유한값·의존성 선언의 제품 코드 보수.
- 공용 SHAP 잠금과 캐시 프로토콜 경계 보수 및 관련 회귀 테스트.
- 새 실행 묶음의 실제 모델 수치 재검증·차분 진단·독립 복구 실행.
- 승인한 추가 후보 비교와 조건부 float64 진단.
- 새 공식 검증 자료의 C:/D: 백업 생성·checksum 확인.
- 경고 UI, 최종 품질 승인, 최종 배포본과 깨끗한 Windows 검증 등 후속 티켓 작업.

## 구현 작업의 시작 순서

1. 위 작업 지침과 원격 #205/로컬 명세·인터뷰를 읽고 Q1~Q17 합의를 유지한다.
2. 실제 통합 기준·영향받는 경계를 확인하고 명세의 보수·공개 경계 회귀를 수행한다.
3. 새 실행 묶음을 사전 등록하고 필수 실제 검증·승인한 추가 조사·근거 보관을 수행한다.
4. 명령·통과/실패/건너뜀·미검증 항목과 후속 담당을 보고한다. 설계 완료를 수치 통과로
   해석하지 않는다. 이 순서는 별도 구현 작업을 위한 것이며 이번 설계 세션에서 시작하지 않는다.

다음 작업 요청 예시: "#205 확정 명세와 인계를 따라 구현해. Q1~Q17 합의와
dashboard_v3/AGENTS.md의 테스트 범위를 유지해."
