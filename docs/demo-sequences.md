# 데스크톱 시연 서열 선정·검증 기록 (#190)

[요구사항 #190](https://github.com/shin584/project/issues/190)의 5개 슬롯을
검증한다. **②·⑤의 조건을 충족하지 못했으므로 #190의
“5개 확정” 완료 조건은 아직 충족하지 않았다.** 아래 ⑤는 확정 서열이 아닌
최저점 예비 후보이며, ②도 검증용 예비 후보다. 기준 완화는 적용하지 않는다.

**모두 합성 서열이며 실제 생물의 표적이나 실험 검증된 절단
효율이 아니다.** ①은 기존 시연 입력을 그대로 유지하고, ②–⑤의 후보는 균일
난수 목록에서 선택한다. PAM을 삽입하는 설계는 하지 않는다.

## 측정 기준과 재현

작업 기준 소스는 `dashboard_core_v2`의
`0ba6d5d1199acee3fd19d3cbd68e7244485a79a6`이며, 2026-11-17에 이 워크트리의
`core` facade와 로컬 모델 두 개로 측정했다. 소스·모델·기존 baseline은
변경하지 않는다. 임시 스크리닝 프로그램과 중간 결과는 Git 제외 경로인
`.packaging/issue190/`에 두며, 문서의 선정 결과가 버전 관리 대상이다.

Python 3.13.7, torch 2.12.0+cpu, transformers 5.8.1, numpy 2.3.2,
shap 0.52.0, CPU 4스레드, 모델 float32/배치 8을 사용한다. Hugging Face는
`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`로 기존 토크나이저만 읽었다.

| 로컬 가중치 | SHA-256 |
|---|---|
| `models/SpCas9.safetensors` | `8a1a84ab4542da1eef9720ab54c785d1d2faa721e43b4731da018ec8b64fe9d9` |
| `models/Cas12a.safetensors` | `eae04f4ff269bd4cf8973b1a219019e6e349272555359878f7ac4ee9f6471969` |

②–⑤의 후보는 Python 표준 `random.Random(190)`으로 아래 순서대로 생성했다.
GC/반복 조건 탈락은 버리고 다음 난수를 뽑는다. **347회 추출 중 300개**가
통과했다. 후보 번호는 이 통과 목록의 1부터 시작하는 번호다. ①은 후보 0으로
별도 측정하며, 난수 생성의 GC/반복 조건도 만족한다.

```python
import random
import re

rng = random.Random(190)
candidates = []
while len(candidates) < 300:
    seq = "".join(rng.choice("ATGC") for _ in range(81))
    gc = (seq.count("G") + seq.count("C")) / 81
    if not 0.4 <= gc <= 0.6:
        continue
    if re.search(r"A{6}|T{6}|G{6}|C{6}", seq) or seq in candidates:
        continue
    candidates.append(seq)
```

300개를 순서대로 LF로 연결하고 마지막 LF를 붙인 ASCII 바이트의 SHA-256은
`8790979a8095d9b83f2d9e2804f527a641caf249a140ea69720e1ca46b9ec9a6`이다.
Cas12a 사이트 수가 0/1/2/3개인 입력은 각각 164/99/33/4개다.
300개 모두 사이트가 5개 이상이고 최소 사이트 수는 8개였다.
기존 입력 ①을 포함한 예측에는 `percentile` 행이 없었다.

`core.scan_all(seq)`와 `core.run_prediction(scan, core.load_predictors(warmup=False))`를
사용한다. 사이트는 **윈도우 생성 가능 + 중심 40에서 거리 15bp 이하**인 것만
센다. 따라서 입력 안의 모든 PAM 일치 개수와 다르다. 모든 예측 행의
`score_kind`는 `efficiency`이며, 표의 %는 모델이 예측한 절단 효율이다.
SpCas9 원출력은 z-score, Cas12a 원출력은 비율이므로 SHAP 수치의 크기를
두 Cas 사이에서 비교하지 않는다.

`site_key`의 PAM 위치는 **검색 가닥의 0부터 시작하는 좌표**다. 특히 `−`가닥
위치를 입력 `+`가닥 위치로 읽지 않는다. `cut_pos`와 `distance`는 코어가
입력 좌표로 환산한 값이며 `distance = abs(cut_pos - 40)`이다.
사이트 순위는 각 사이트의 최고 효율 예측 행을 효율·원출력 내림차순으로
정렬한 것이다. 예측 행 수와 사이트 수를 구분한다.

신규 SHAP은 `core.kernel_shap(handle, window, nsamples=64,
n_background=4, seed=0)`로 측정하며 **각 호출 직전 `numpy.random.seed(190)`**을
설정한다. 배경 생성의 seed=0과 KernelSHAP 마스크 추출의 전역 난수 seed는
별개다. |SHAP| 내림차순의 1부터 시작하는 순위와
`mean(abs(values[PAM])) / mean(abs(values))`로 합격선을 계산한다.
기존 ①은 재계산하지 않고 저장된 값을 사용한다.

64샘플 설정에서 기존 특이행렬 경고가 재현된다. 기여도는 이 모델·배경·샘플
설정에서의 관측이며, 샘플 수를 올리거나 SHAP을 다시 계산하면 값과 순위가
달라질 수 있다. 낮은 가산성 오차만으로 기여도 추정의 안정성을 보증하지 않는다.

## Cas12a 좌표 확인 사항

현 소스의 `pam_scanner.extract_model_input_window()`는 Cas12a 윈도우를
검색된 `TTTV` 시작점에서 잘라 **0–3번**에 `TTTV`를 둔다. 반면
`core.WINDOW_LAYOUT["Cas12a"]`와 화면 차트의 PAM 색 구간은 **4–7번**이다.
이슈 배경의 4–7번 구간을 실제 검색된 `TTTV`라고 해석하면 다른 염기의
기여도를 PAM 기여도로 잘못 설명하게 된다. 본 문서는 두 구간을 구분한다.
이 티켓은 문서화만 하므로 좌표 계약은 변경하지 않는다.

## 입력과 각본

### ① SpCas9 PAM 기여도 — 기존 대표 서열

```text
CAAAGTAGCCGGTCGCTTTAAGAATAAATAAAAGCGCCACAGGATTGACTAAACCACAGCCGGCGCCCTGGCCCCCTACCG
```

81bp, GC 54.32%, 동일염기 최대 5연속. 사이트 **13개**: SpCas9 +6/−5,
Cas12a +1/−1. 예측 행 38개. 최고 효율은 `SpCas9|+|32`의 **SpCas9-NG
51.988960%**, PAM `AGC`, 절단 위치 29, 거리 11bp다. 이 사이트가 XAI의
첫 사이트이고 호환 출력 목록의 첫 출력도 SpCas9-NG다.

윈도우 `CCGGTCGCTTTAAGAATAAATAAAAGCGCC`의 기존 캐시
`e751bae6f380e425.npz`를 그대로 읽었다. SHAP은 모델 원출력 단위다.

| PAM 위치 (0부터) | 염기 | SHAP | 윈도우 내 절대값 순위 |
|---|---|---:|---:|
| 24 | A | +0.503745 | 4 |
| 25 | G | +0.970634 | 1 |
| 26 | C | −0.377741 | 6 |

PAM 평균 |SHAP| **0.617373** / 윈도우 평균 **0.196618** = **3.139969배**.
NGN의 불변 G가 1위이며 합격선(1위 + 2배)을 넘는다. 설명 문구는
“이 모델의 예측에서 PAM 위치가 크게 기여한다”로 한다. 음의 기여도도 있으므로
PAM 세 염기가 모두 예측을 올린다고 말하지 않는다. 모델 설명은 생물학적
절단 메커니즘을 실험으로 증명한 결과가 아니다. 기존 서열 유지이며 폴백 없음.

### ③ WT가 못 쓰는 PAM — 난수 후보 28

```text
GCGATGGCCCGGCCGTCTTCCGCATCGAGCCAACCTTCTGTAAGAGGGGAACCAGGTAAGGAGCCAAAACTTTATAAAGCG
```

81bp, GC 55.56%, 동일염기 최대 4연속. 사이트 **19개**: SpCas9 +9/−8,
Cas12a +0/−2. 예측 행 82개. 최고 효율은 `SpCas9|+|42`의 **VRQR
66.191813%**, PAM `AGA`, 절단 위치 39, 거리 1bp다. 윈도우는
`TCCGCATCGAGCCAACCTTCTGTAAGAGGG`다.

변종 비교에서 이 사이트의 행을 가리킨다.

| 출력 | 예측 절단 효율 |
|---|---:|
| SpCas9(WT) | 빈 칸 (PAM 비호환) |
| SpCas9-NG | 50.654007% |
| VRQR | 66.191813% |
| xCas9 | 34.101366% |
| Sniper·SpCas9-HF1·eSpCas9(1.1)·HypaCas9·evoCas9 | 빈 칸 (PAM 비호환) |

빈 칸은 0% 예측이 아니라 **예측 행 자체를 만들지 않은 것**이다. 같은 입력의

출력을 둔다.” SHAP은 선정 기준이 아니며 측정하지 않았다. 난수 선택으로
충족했으므로 PAM 삽입 설계 폴백은 사용하지 않았다.

### ④ 거리와 효율의 트레이드오프 — 난수 후보 40

```text
TGTTAGAACGTGGGAACGAGCTAGTACATGCAGAGGTGCTCGCTCGCTGAAAGATTTGAAGGGTATAAGGAGGGTCAGAGC
```

81bp, GC 50.62%, 동일염기 최대 3연속. 사이트 **18개**: SpCas9 +10/−7,
Cas12a +0/−1. 예측 행 47개. 아래 효율은 각 사이트의 최고 효율 출력이다.

| 사이트 | PAM | 출력 | cut_pos | 중심과 거리 | 효율 |
|---|---|---|---:|---:|---:|
| `Cas12a\|-\|29` | TTTC | Cas12a | 27 | 13bp | **57.918030%** |
| `SpCas9\|-\|41` | AGC | SpCas9-NG | 42 | **2bp** | 22.607248% |
| `SpCas9\|+\|44` | CGC | SpCas9-NG | 41 | **1bp** | 18.386036% |

전체 사이트 1위는 멀리 있는 Cas12a다. 가까운 사이트 중 가장 높은 효율은
22.607248%로, 두 사이트의 차이는 **35.310783%p**다. Best Candidates에서
최고 효율과 거리를 함께 보고, 전체 상세 보기에서 거리 조건을 0–2bp로
바꿔 두 가까운 사이트를 비교한다. 현재 정렬에는 거리 보정이 없으므로
“가장 높은 효율이 항상 중심에 가장 가까운 것은 아니다”라고 설명한다.
SHAP은 선정 기준이 아니며 측정하지 않았다. 원래 트레이드오프 조건을
만족하므로 “가까운 사이트가 상위 3위”로 완화하는 폴백은 사용하지 않았다.

### ⑤ 저점수 — 미충족, 최저점 예비 후보 141

```text
AAACGAGGGAAATCCTTCATGAGAAGAGGCCTAGATTGCAGATATATTTTCTAACACGGATGACAGCCTTATCAACGGTTG
```

81bp, GC 41.98%, 동일염기 최대 4연속. 사이트 **9개**: SpCas9 +5/−4,
Cas12a +0/−0. 예측 행 34개. 최고 효율은 `SpCas9|-|49`의 **SpCas9(WT)
42.964001%**, PAM `AGG`, 절단 위치 34, 거리 6bp다. 윈도우는
`TGTTAGAAAATATATCTGCAATCTAGGCCT`다.

**20% 이하 조건에 실패한다.** 낮은 개별 행(`SpCas9|+|32`, 15.896752%)이
있어도, 전체 최고값이 42.964001%이므로 이 입력을 “최고 효율 20% 이하”의
시연으로 쓰면 안 된다. 사이트 5개 이상 조건은 충족한다.

| 난수 후보 | 전체 최고 효율 | 사이트 수 |
|---|---:|---:|
| 141 | 42.964001% | 9 |
| 117 | 43.284967% | 14 |
| 145 | 44.897264% | 15 |
| 48 | 46.052537% | 14 |
| 229 | 47.062570% | 14 |

이는 300개 탐색에서의 관측이며, 조건을 만족하는 서열이 수학적으로 존재하지
않는다는 결론이 아니다. 이슈가 합의한 폴백은 ③·④에만 있으므로, ⑤를
“300개 중 최저점”으로 바꾸거나 GC/반복 조건을 풀지 않았다. 추가 탐색 또는
⑤ 기준 변경이 합의되어야 최종 확정할 수 있다.

요청된 ⑤의 SHAP 1회 측정은 이 예비 후보의 최고 효율 출력 SpCas9(WT)에
대해 수행했다. PAM `AGG`의 24/25/26번 SHAP은 각각 **−0.142991,
+0.920172, +0.324786**, 절대값 순위는 **14/1/7위**다. PAM 평균 절대 SHAP
**0.462650** / 윈도우 평균 **0.213715** = **2.164800배**로 PAM 기여도
합격선은 넘는다. 그러나 최고 효율 20% 이하 조건 실패를 대신하지 못한다.
이 신규 SpCas9(WT) 결과는 `make_precomputed_shap.py`의 Cas12a 전용 범위에
포함되지 않으며, 시연용 새 캐시로 배포하지 않았다.

신규 SHAP 완료는 ② 8회 + ⑤ 1회 = **9회**다. 초기에 메모리 경합으로
중단한 시도 1회를 포함해도 **총 10회**를 넘지 않았다. ①은 기존 캐시 읽기이며
추가 SHAP 계산이 없다. 신규 결과는 `.packaging/issue190/shap/`에 보존했고,
기존 `data/precomputed_shap/`와 baseline 파일은 변경하지 않았다.

  `python make_precomputed_shap.py <서열①> <서열②>
  <서열③> <서열④> <서열⑤>`에 전달한다. 이 스크립트의 `TARGET_CAS`는
  `("Cas12a",)`이므로 **Cas12a 사이트 전체**만 저장한다. Cas12a가 없는 입력은
  건너뛰며 실패가 아니다. SpCas9 전체의 사전계산을 만들었다고 설명하지 않는다.
- [ ] ①의 SpCas9-NG SHAP 캐시
  `data/precomputed_shap/e751bae6f380e425.npz`가 있는지 확인한다. 캐시 키는
  `A/SpCas9|SpCas9-NG|CCGGTCGCTTTAAGAATAAATAAAAGCGCC|64|4`다.
- [ ] `python -m desktop`으로 소스 실행을 시작하고 모델 준비 완료를 기다린다.
  5개 입력을 한 번씩 분석해 실제 예측을 확인한다. ①의 XAI에서
  `SpCas9|+|32`, `SpCas9-NG`를 선택해 **IG 32단계**를 한 번 실행한다.
  이 준비 실행으로 SpCas9 지연 로딩과 첫 추론 비용도 미리 소모한다.
- [ ] 시연에 쓸 SHAP·Rollout도 지정 사이트/출력에서 한 번씩 열어 둔다.
  SpCas9의 다른 사이트/출력은 별도의 키이므로 ①의 캐시로 커버되지 않는다.
- [ ] **같은 데스크톱 프로세스를 유지하고 시연 중 재시작하지 않는다.**
  IG에는 디스크 캐시가 없다. 준비 명령을 별도 Python 프로세스에서 실행해도
  데스크톱의 IG 메모리 캐시는 채워지지 않는다.
- [ ] **SHAP 샘플 64·배경 4, IG 32단계를 유지하고 계산 설정 입력을 건드리지
  않는다.** SHAP 디스크 키는 `(model_key, head, window_seq, nsamples,
  n_background)` 다섯 값 전부이며 `seed=0`일 때만 조회된다. IG 단계 수는
  IG 메모리 키에 포함되며 SHAP 디스크 키에는 포함되지 않는다.
- [ ] IG는 ①에서만 연다. 다른 네 입력에서도 라이브 IG를 준비하는 작업이나
  IG 디스크 캐시 추가는 이번 시연 범위에 포함하지 않는다.
