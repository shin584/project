# #189 배치·진행률 검증

작업 기준점은 `5faeeec50e402325ef7659795cacaf6208f27495`, 작업 브랜치는
`dashboard_core_v2`다. 실제 모델 두 개를 사용하는 소스 실행의 WebView2 창에서
확인했다. #188의 기존 exe를 다시 빌드한 증거는 아니다.

## 실제 창

창 설정은 기본 **1280×840**, Windows 배율은 125%다. 네이티브 캡처는 실제 화면의
픽셀 크기이며, DOM을 다른 브라우저에서 재렌더한 그림이 아니다. 그래프 크기는
80%, IG 32단계, SHAP 64샘플·배경 4개를 유지했다. 배경 설명과 계산 설정은 기본
접힘 상태다. 입력은 #181의 `capture.json`에 기록한 고정 81bp 서열이다.

- [예측 진행 중](01-prediction.png): 기존 제목 아래 작업명·숫자 퍼센트·막대·취소 버튼.
- [Best Candidates](02-best-candidates.png): PAM 제목·개수·후보표 펼침·점수 안내·
  모델 출력 해석 펼침·대표 결과표 순서.
- [IG 진행 중](03-xai-ig-running.png): 진행률과 분석 대상·출력·모델 입력 구간·
  점수 요약·계산 설정 요약을 함께 확인한다.
- [IG 완료](04-xai-ig-completed.png): 진행 영역을 정리하고 입력 구간을 설정 위에 유지한다.

차트 전체나 펼친 계산 설정의 모든 입력이 한 화면에 들어오는 것은 요구하지 않는다.
IG 계산 중 가시 영역은 1266×803 CSS px이고, 입력 구간은 y=515~617,
계산 설정 요약은 y=717~737에 있어 진행률과 함께 창 안에서 확인할 수 있었다.
새 고정 영역은 추가하지 않았다. 모델 입력 구간은 첫 설명 결과가 생성될 때 배치하고,
같은 사이트의 재계산에서는 유지한다. 사이트 변경·새 분석에서는 이전 구간을 지운다.

## 이벤트와 상태

[validation.json](validation.json)에 소스 해시·창 크기·진행 이벤트·DOM 가시 영역과
실제 네이티브 캡처 범위를 기록했다. 관측기는 기존 공개 호출과 이벤트를 전달하며,
스크린샷을 찍기 위해 이벤트 사이에 짧은 지연을 둔다. 모델 수치나 진행 카운터는
대체하지 않았다.

첫 예측 이벤트는 **8/13 → 11/13 → 13/13**, 화면은 **61% → 84% → 100%**다.
분모는 두 모델에서 처리할 입력 서열 수의 합이며 예측 행 38개의 비율이 아니다.
모델 로딩이나 배치 내부 진행률은 추가하지 않았다.

다른 세 탭에서 PAM 영역·후보표·모델 출력 해석 상태가 숨겨지고, 탭을 바꿔도
새 호출이 발생하지 않았다. IG 완료 후 작업 문구는 빈 문자열, 막대 value는 제거,
영역은 숨김 상태다.

예측 중 취소 버튼으로 정리한 상태와 재시도도 관측했다. 오류 정리는 공개
`onEvent`에 현재 요청 ID의 오류 이벤트를 넣어 확인했다. 이 오류 항목은 실제 모델
오류를 유발한 실험이 아니다. 취소·오류 뒤 이전 ID의 진행 이벤트를 전달해도 표시가
되살아나지 않는지 함께 기록했다.
